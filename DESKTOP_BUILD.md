# PDF Suite — Desktop Packaging (Tauri 2)

This turns the web app into a real Windows `.msi`/`.exe` installer or
macOS `.dmg`, using [Tauri 2](https://v2.tauri.app) — a Rust shell that
wraps the existing React/Vite app in a native window using the OS's own
web engine (WebView2 on Windows, WKWebView on macOS), instead of bundling
a whole separate Chromium like Electron does. Result: a much smaller,
faster-starting installer.

**Important, read first:** I built and validated everything in this
`src-tauri/` folder that could be checked without a native OS — the
Tauri CLI itself ran here and confirmed the project structure, config,
and icons are all correct. But an actual `.msi`/`.exe` can only be
compiled *on Windows*, and a `.dmg` only *on macOS* — that's a hard
constraint of how native app bundling works (Tauri's Windows bundler
needs the Windows SDK/WiX or NSIS; the macOS bundler needs Xcode's
codesigning tools). I can't produce the compiled installer file myself
in this sandbox; the steps below are what you'd run yourself.

## What's already done for you

- `src-tauri/` — the full Tauri 2 Rust project, generated by the real
  Tauri CLI (not hand-written from scratch) and then customized:
  product name "PDF Suite", identifier `com.adlabs.pdfsuite`, version
  `1.2.11`, 1440×900 default window, publisher "AD Labs"
- `src-tauri/icons/` — a complete icon set (`.ico` for Windows, `.icns`
  for macOS, various `.png` sizes) generated from your logo via Tauri's
  own icon tool
- `package.json` — has an `npm run tauri` script and `@tauri-apps/cli`
  installed as a dev dependency

## Building the Windows installer (.msi and .exe)

### 1. Install prerequisites (one-time, on the Windows machine you'll build on)

**Rust** — via [rustup.rs](https://rustup.rs), the standard Rust
installer. Download and run `rustup-init.exe`, accept the defaults.
Then close and reopen PowerShell.

Verify:
```powershell
rustc --version
cargo --version
```

**Microsoft C++ Build Tools** — Tauri needs a native linker.
Download "Build Tools for Visual Studio" from
https://visualstudio.microsoft.com/visual-cpp-build-tools/
Run the installer, and check **"Desktop development with C++"** in the
workload list, then install (a few GB, takes a while).

**WebView2** — almost certainly already installed if you're on Windows
10 (recent update) or Windows 11. If `tauri info` (see below) flags it
missing, get it from
https://developer.microsoft.com/microsoft-edge/webview2/

### 2. Get the project and install JS dependencies

```powershell
cd "C:\Users\anoodh\Documents\pdfsuite-branding"
npm install
```

### 3. Sanity-check the environment

```powershell
npx tauri info
```
Everything under "Environment" should show a green checkmark. If Rust or
the C++ Build Tools show an X, fix that before continuing (the error
messages are usually specific about what's missing).

### 4. Build

```powershell
npm run tauri build
```
First run takes a while (compiling Rust + all dependencies, maybe
5–15 minutes depending on your machine). Subsequent builds are faster.

### 5. Find your installers

```
src-tauri\target\release\bundle\msi\PDF Suite_1.2.11_x64_en-US.msi
src-tauri\target\release\bundle\nsis\PDF Suite_1.2.11_x64-setup.exe
```
Both are real installers — either works; MSI is generally preferred for
enterprise/Group Policy deployment, the NSIS `.exe` is a more familiar
"double-click to install" experience.

## Building the macOS installer (.dmg)

Needs an actual Mac (Tauri's macOS bundler uses Apple's own codesigning
tools, which don't run on Windows/Linux).

### 1. Prerequisites (one-time, on the Mac)
```bash
xcode-select --install
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```
Restart your terminal after the Rust install.

### 2. Build
```bash
cd path/to/pdfsuite
npm install
npm run tauri build
```

### 3. Find it
```
src-tauri/target/release/bundle/dmg/PDF Suite_1.2.11_aarch64.dmg
```
(or `x64.dmg` if building on an Intel Mac)

**Code signing note**: an unsigned `.dmg` will trigger a Gatekeeper
warning ("unidentified developer") on other Macs. For internal office
distribution this is usually fine (right-click → Open bypasses it once),
but if that's a problem for your users, real distribution needs an Apple
Developer account ($99/year) and a Developer ID certificate — a separate
step from anything here, ask if you want to go down that path.

## Distributing to office workstations

Once you have the `.msi` (recommended for offices):

- **Simplest**: put it on a shared network drive or send it directly;
  users double-click to install, same as any other Windows software.
- **IT-managed rollout**: `.msi` files work with Group Policy Software
  Installation or tools like Intune/SCCM for pushing to many machines at
  once without each user running the installer manually — ask your IT
  team if that infrastructure already exists.
- **Updates**: each new version needs a new build + redistribution.
  Tauri does support an auto-updater plugin (checks a URL you host for
  new versions and self-updates) — not set up here since it needs a
  place to host update manifests/files, but it's a real, well-supported
  Tauri feature if ongoing updates become a hassle to distribute manually.

## Things to test once you have a build running

A few behaviors that work fine in a browser tab can behave differently
inside a native app window — worth specifically checking, not just
trusting they carried over:
- **Print** (uses `window.open` + the browser's print dialog) — confirm
  this still opens correctly in the native window
- **Share…** (Web Share API) — likely *won't* work the same way inside
  Tauri's webview, since that API is designed for browser share sheets;
  Email and Save-As-then-attach will still work as fallbacks
- File open/drag-and-drop — should work identically, standard web APIs
- OCR (Tesseract.js) — downloads its language data from a CDN on first
  use; confirm office workstations have internet access for that, or
  ask if you want it bundled locally instead so it works fully offline

## Local dev mode (test without building an installer)

```powershell
npm run tauri dev
```
Opens the app in a native window pointed at your live dev server —
useful for quickly checking things look/behave right before running a
full `tauri build`.
